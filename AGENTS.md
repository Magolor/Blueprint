# Blueprint Agent Guide Scaffold

This file is a scaffold placeholder. When creating a new project from Blueprint, rewrite `AGENTS.md` for that project's concrete purpose, docs map, commands, risks, and team workflow. Keep only the policies that still apply.

## Initialization Checklist

1. Replace this title with `<Project> Agent Guide`.
2. Point agents to `docs/README.md` first when the project has docs.
3. Replace template package paths such as `src/blueprint/` with the real import package.
4. Record the real GitHub remote, default branch, issue tracker, and release policy.
5. Keep environment commands aligned with `pyproject.toml`, `scripts/`, and CI.
6. Describe project-specific source-of-truth docs under `docs/goals/`, `docs/resources/`, and `docs/progress/`.
7. Remove any section that is not true for the new project.

## Environment

Source of truth: **`requirements.txt` and `requirements-dev.txt`**. `pyproject.toml` references them through setuptools dynamic metadata.

Install priority: **uv -> pip (requirements) -> pyproject -> conda -> poetry**.

- **Edit:** change `requirements.txt` (runtime) and `requirements-dev.txt` (dev extra), then run `bash scripts/sync-env.bash`.
- **uv:** `uv.lock` is generated from the requirements sources; `bash scripts/sync-env.bash` runs `uv sync --all-extras` by default.
- **pip:** install from `requirements*.txt` or `pip install -e ".[dev]"`.
- **pyproject:** package metadata and extras wiring only; do not duplicate dependency pins inline.
- **conda:** `environment-dev.yml` is a generated thin adapter with `-e ".[dev]"` only.
- **poetry:** optional; `poetry.lock` is regenerated by `bash scripts/sync-env.bash` when Poetry is installed.
- `scripts/sync-env.bash --check` is the CI drift gate for generated lockfiles and conda output.
- Treat `heavenbase==0.1.1.0` as a normal PyPI runtime dependency.
- Use `scripts/sync-env.bash --heavenbase-source` only as a temporary local source override for HeavenBase development; it may fail when the sibling checkout, network, proxy, or Git credentials are unavailable.
- Keep the package version in `src/blueprint/version.py`; `pyproject.toml` reads it dynamically.
- **Versioning:** `MAJOR.MINOR.PATCH.N[devK]` (currently `0.1.1.0`), aligned with HeavenBase when version bumps are intentional. Optional `devK` marks in-development snapshots.
- Keep `README.en.md` as the canonical English README source. `README.md` is generated from it.
- For package-resource README copies, use `scripts/sync-readme.bash --resource-target <import_name>` or `scripts/sync-env.bash --readme-resource-target <import_name>`.
- Maintain translated docs such as `README.zh.md` through `.agents/skills/heaven-style/references/tasks/doc-trans.md`, not during ordinary English doc sync. Use `.agents/skills/heaven-style/references/tasks/doc-sync.md` for canonical English docs.

## Docs

- `docs/README.md` is the project docs menu and authority map.
- `docs/goals/` holds long-, mid-, and short-term goals.
- `docs/resources/` holds stable external/internal references and domain background.
- `docs/progress/` holds progress notes by day: `docs/progress/YYYY-MM-DD/README.md` is the daily summary, with detailed notes beside it when needed.
- Before docs-sensitive work, check or ask which docs sources matter: current goals, latest progress, feature requests or issue tracker, stable resources, canonical README/docs source, and translation status.
- Do not create generic `docs/workflows/` or `docs/plans/` in the template. Add them only when a concrete project needs them.

## Linear

- For continuous Linear issues, keep one rolling status comment per issue and edit that comment as work progresses.
- Do not pile up new comments for routine progress, verification, or small status changes.
- Add a new Linear comment only for a distinct decision, handoff, blocker, or user-requested update that should remain separate.

## Commands

Prefix shell commands with `rtk` when working in local agent sessions that provide it.

```bash
rtk bash scripts/sync-env.bash
rtk bash scripts/flake.bash --ci
rtk bash scripts/test.bash
rtk uv build
rtk bash scripts/release.bash
```

For new Bash wrappers, source `scripts/_env.bash` and use its helpers instead of calling `python` directly. The shared Python lookup is: active virtualenv, repo `.venv`, `uv run python` or `uv.exe run python`, then system Python as a last fallback. Hooks may set `REPO_PYTHON_PREFERENCE`, `BLUEPRINT_PYTHON_PREFERENCE`, or `HEAVENBASE_PYTHON_PREFERENCE` to `uv-first` when they need to prefer `uv run python`. Coding-agent shell policy also lives in `.agents/skills/heaven-style/references/rules/project/environment.md`.

## Project Rules

- Repo-local skills live under `.agents/skills`; do not create `.github/skills`.
- Keep `.agents/` trackable; `.gitignore` must not ignore repo-local skills.
- The default repo-local skill is `.agents/skills/heaven-style`; Blueprint is the canonical source. After skill edits, run `python .agents/skills/heaven-style/scripts/install.py` for the versioned global install at `~/.agents/skills/heaven-style-<version>/`, and `python .agents/skills/heaven-style/scripts/install.py --mirror ../HeavenBase/HeavenBase/.agents/skills/heaven-style --skip-global` to refresh the HeavenBase in-repo copy.
- GitHub-specific files live under `.github`.
- Git hooks live under `.githooks`; the pre-commit hook runs `scripts/sync-env.bash --no-heavenbase`, stages generated README/env files, then runs `scripts/flake.bash --all`.
- PyPI publishing is gated to the `release` branch through `.github/workflows/release.yml`; `scripts/release.bash` fast-forwards `release` from clean `master`.
- Python package code is the default SDK surface; CLI commands are the default user/developer surface.
- Keep the default `blueprint-gui` placeholder acceptable, but do not add more GUI, REST, MCP, LSP, VS Code, or desktop app scaffolding unless the project explicitly needs it.
- Put stable demo fixtures in `demos/assets/`.
- Put demo-generated runtime data in `demos/.temp/`.
- Keep `templates/` out of the starter unless a future project has a concrete domain-specific need.
- Prefer `pyproject.toml` over `pytest.ini` or `setup.cfg` unless a tool cannot use it.
