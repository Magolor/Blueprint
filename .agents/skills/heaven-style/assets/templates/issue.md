# Issue body

## Summary

Summarize the affected feature, the problem or request, and who needs the outcome.
Identify whether the issue reports a bug, requests a feature, or asks a question.

## Context and evidence

Locate the system responsibility and explain the observed behavior. For bugs,
include the trigger, minimal reproduction, relevant revision/environment, and
actual result. For requests, explain the use case. For questions, explain what
was tried. State unknowns; keep logs short and remove sensitive data.

## Expected outcome

Describe the desired behavior and observable resolution conditions. Do not invent
acceptance checklists for an open question. Distinguish suspected causes and
suggested fixes from verified facts. Link detailed investigation when it exists.

## References

Link related issues, canonical docs, and the existing task owner. If the issue
is the repository's task authority, keep its state here; otherwise do not copy
the queue's evolving execution checklist.
