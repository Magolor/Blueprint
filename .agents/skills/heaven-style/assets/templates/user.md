# User guide

## Summary

Explain what readers can accomplish, when the feature helps, and its main boundary.

## Use the feature

State prerequisites and give the shortest safe sequence through supported
commands or UI actions. Explain identifiers when readers need them. Keep
consequential limits, costs, and warnings beside the affected step.

## Results and recovery

Show observable success, likely failures, and recovery. Explain unsupported
cases and relevant compatibility or migration requirements.

## References

Link related user guidance and canonical reference owners. Link optional
developer detail here, or place a short named fold after the user path when
helpful. Never hide required instructions or warnings in that fold.
