# Contract reference

## Summary

Explain what consumers can rely on and where the contract applies. Distinguish
shipped behavior, accepted target, and gaps before showing examples.

## Ownership and semantics

Introduce the concept and authority. State inputs, outputs, invariants, lifecycle,
and failures. Include concurrency and cancellation where material. Link source
schemas or generated catalogs instead of duplicating exact member inventories.

## Use and boundaries

Show a supported use or clearly labeled proposed sketch. Explain unsupported
cases and compatibility obligations. Add a state diagram or focused example
only when it resolves ambiguity.

## Verification

Link behavioral evidence or review criteria and identify unimplemented promises.

## References

Link the source/API owner, design, decision, and consumer guide.
