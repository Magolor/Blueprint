# Decision record

## Summary

Summarize the choice and its consequence. Use the repository's existing status,
identifier, date, and decision-owner fields. Reserve this artifact for a durable, consequential architectural or project choice at the same scope as its peers. Refine an existing choice in its owner; routine implementation and slice history belong in technical docs or the development log.

## Context and options

Explain the decision pressure and constraints. Compare credible alternatives
against the same criteria. Link the full design and evidence.

## Decision

State the selected or recommended option and why. Distinguish a proposal from
an accepted disposition, and identify unresolved choices and their owner.

## Consequences

Describe benefits, costs, risks, and revisit conditions. Include compatibility,
refinement, or supersession when relevant, using repository semantics. Preserve
prior rationale rather than rewriting history into agreement.

## References

Link related decisions, source snapshots, the design, and an execution plan
when implementation is authorized. Do not create a competing decision index.
