# Overview

## Summary

Explain what the system or module enables, who uses it, and its principal boundary.

## Start here

Locate the subject in the larger product and give one recommended entry path
with prerequisites and an observable result.

## Mental model

Introduce the smallest set of concepts, their responsibilities, and relationships.
Explain names as they appear. Add a diagram only when it makes those relationships
clearer.

## References

Provide a short reading path with one purpose per link. Aim for three to five
files that orient a newcomer to a local module; this is not a limit on required
skill or architecture reading. Link deeper contracts without duplicating them.
