# Architecture check

## Summary

State one invariant and the problem it prevents.

## Rule and scope

Name the responsible boundary, allowed and forbidden behavior or dependencies,
and meaningful exceptions. Give a contrasting example only when it clarifies
the distinction.

## Evidence

Explain what a reviewer should inspect and link an existing focused check where
available. Do not create a validator solely because this document exists.

## References

Link the normative contract or design. Keep this a compact review aid rather
than a competing copy of the rule.
