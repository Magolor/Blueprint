# Self-edit

## Summary

Improve the canonical skill while preserving its contracts, reading paths, and declared installations. Keep maintenance changes within the repository’s version policy.

## Tasks

1. Inspect the requested change and existing owners. For a hierarchy or multi-slice change, use [design](../tasks/design/docs.md) and one linked [plan](../tasks/design/plan.md) to record the accepted scope and retention checks.
2. [Edit the skill](../tasks/edit/README.md). Keep each rule in one owner, task manuals under their tasks, and workflow sequences across distinct tasks. Repair references when moving files and regenerate the index.
3. [Proofread](../tasks/proof.md) changed material and follow representative role → workflow → task paths. [Review](../tasks/review.md) changed executable helpers; [triage](../tasks/triage.md) and [address](../tasks/address.md) material findings.
4. [Sync](../tasks/sync/README.md) declared branch copies and installations using the maintenance manual. Run every required branch gate and verify exact distributed content. Record the outcome in the canonical log.

## Acceptance and stopping

Vital contracts remain discoverable, all local routes resolve, relevant checks pass, and declared copies match. Keep the frozen version when policy requires it. A blocked gate or projection remains explicit; do not report partial installation as complete.
