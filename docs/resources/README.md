# Resources

Use this folder for stable project references and background.

Resources are the durable source of truth for facts that should survive beyond one task or day.

Good candidates:

- domain notes;
- source-of-truth links;
- architecture references;
- migration inventories;
- external specifications.

Create subfolders only when the project has enough stable material to justify them, such as `architecture/`, `specifications/`, or `inventories/`.

Do not put task state, temporary notes, active plan checklists, or one-off review findings here. Use `docs/tasks.yaml` for active work, `docs/DEVLOG.md` for concise handoff evidence, `docs/scratch/` for expiring notes, `docs/plans/` for executable detail, and `docs/reports/` for auditable findings. Promote only durable conclusions into resources.
